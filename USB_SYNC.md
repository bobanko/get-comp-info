# Синхронизация с флешкой

Запускай `sync-usb.BAT` или пункт «Синхронизировать с USB» из программы на компьютере **или на флешке**. Направления одинаковы: данные идут с флешки на компьютер, программа — с компьютера на флешку.

При запуске с компьютера скрипт автоматически ищет подключённые съёмные и USB-диски независимо от буквы. В корне каждого диска ищет папки `COMP-INFO` или папки с `sync-usb.ps1`; если таких папок нет, предлагает `COMP-INFO` на этом диске. Единственный вариант выбирается автоматически, при нескольких вариантах нужно выбрать номер или ввести полный путь. Если флешка не найдена, можно указать путь вручную; пустой ввод отменяет синхронизацию. Для папок глубже первого уровня используйте ручной путь.

Путь можно передать явно: `sync-usb.BAT -UsbPath "F:\COMP-INFO"`. Если папки нет, скрипт создаст её, но сам диск должен быть подключён. Разбор сохранённых конфликтов на компьютере не требует флешки.

После успешной синхронизации флешка запоминает путь к программе на компьютере в `sync-targets.json`, отдельно для каждого компьютера и пользователя. При запуске с флешки используется её текущая папка, поэтому изменение буквы диска не мешает. Если сохранённого пути нет или он недоступен, скрипт попросит указать папку программы на компьютере. Можно передать её сразу: `sync-usb.BAT -ComputerPath "C:\Tools\COMP-INFO"`.

Первоначально обнови флешку запуском синхронизации с компьютера. Для запуска с флешки нужна локальная копия программы с поддержкой `-ComputerPath`; скрипт передаёт ей выполнение, чтобы обновлять файлы на флешке из локальной версии. Флешка определяется по сохранённым настройкам, съёмному диску или совпадению с `-UsbPath`. Если внешний диск определяется как обычный диск и ещё не настроен, укажи `-ComputerPath` явно.

Перед запуском закрой сборщик и просмотрщик на обоих устройствах. Дождись завершения синхронизации перед извлечением флешки.

## Как объединять изменения

Новые записи из `data` на флешке добавляются автоматически. Записи с одинаковыми значениями пропускаются: порядок ключей JSON и форматирование не считаются изменением. Даты, пустые значения и отсутствие поля учитываются как данные.

Если значения различаются, скрипт показывает таблицу «Поле | На компьютере | С флешки», как при повторном сохранении данных. Отличающиеся строки выделены жёлтым, совпадающие — серым. Длинные значения переносятся внутри столбцов. Стрелками и Enter выбери действие:

- **Выбрать значения по полям** — для каждого отличающегося поля показываются обе версии. Выбери локальное значение или значение с флешки. Esc возвращает к предыдущему полю, а на первом поле — к выбору действия.
- **Принять запись с флешки** — заменить локальную запись целиком.
- **Оставить локальную запись** — сохранить текущие данные компьютера и запомнить решение.
- **Отложить** — сохранить входящую версию для последующего разбора и продолжить синхронизацию.

Перед сохранением показывается такая же таблица «На компьютере | После сохранения» с подсветкой итоговых изменений. Подтверди «Сохранить решение» или вернись назад. Перед заменой локального файла его предыдущая версия сохраняется в `sync-backups` и проверяется по SHA256.

В конце отображается количество добавленных, обновлённых, оставленных локальных и отложенных записей.

## Как вернуться к отложенным конфликтам

На основном компьютере открой главное меню и выбери **«Разобрать конфликты синхронизации»**. Подключать флешку не нужно. Можно также запустить:

```powershell
.\sync-usb.ps1 -ReviewConflicts
```

Этот режим разбирает сохранённые версии без обновления программы на флешке. Обычная синхронизация также включает отложенные конфликты. Старые файлы из `sync-conflicts\<имя записи>\*.json` автоматически участвуют в разборе. Если для одного компьютера сохранено несколько разных версий, они разбираются отдельно; проверяй дату сбора. Если локальная запись отсутствует, восстановление архивной версии требует подтверждения.

Принятые решения сохраняются в `sync-state`. Та же входящая версия больше не вызывает вопрос, даже если локальную запись позже редактировали. Если на флешке значения изменились, появляется новый разбор. Форматирование файла не сбрасывает решение. Одинаковые входящие версии обрабатываются один раз за запуск.

Папки `sync-state`, `sync-conflicts` и `sync-backups` — служебные данные основного компьютера. Не нужно вручную переносить из них значения для обычного разбора. Сохраняй эти папки вместе с проектом; удаление `sync-state` приведёт к повторным вопросам. Архивы и резервные копии автоматически не удаляются. Файл `sync-targets.json` хранится на флешке, исключён из Git и содержит только пути к локальным копиям программы.

## Что переносится

После обработки записей скрипт обновляет корневые `.ps1`, `.bat` и `.cmd` файлы программы на флешке. Данные с компьютера на флешку не копируются. `.git`, документация, тесты и служебные папки не переносятся. Устаревшие файлы не удаляются.

Каждая копия проверяется по SHA256. Изменённые JSON записываются через временный файл с заменой после успешной сериализации. Если запись изменили во время её интерактивного разбора, скрипт останавливается вместо перезаписи. Ошибочный JSON и несовпадающие непустые `computerId` также останавливают обработку.

При ошибке код завершения — 1; уже выполненные операции сохраняются. После устранения причины можно повторить запуск. Git и интернет не нужны.

Это первый этап мерджа: автоматического выбора по дате и объединения по общей предыдущей версии пока нет. Различающиеся записи требуют решения пользователя; принятое решение запоминается.
