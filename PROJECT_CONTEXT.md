# Computer Inventory Collector

## Назначение проекта

Computer Inventory Collector — это portable-утилита для сбора информации о компьютерах во время их подготовки и выдачи сотрудникам.

Основная задача проекта — максимально упростить процесс инвентаризации рабочих станций без необходимости устанавливать дополнительное программное обеспечение.

Утилита запускается непосредственно с USB-флешки, собирает информацию о компьютере и сохраняет её в JSON-файл на эту же флешку.

В дальнейшем собранные данные импортируются во внутреннюю систему компании на Node.js для учета компьютеров, пользователей и обработки заявок.

---

# Основной сценарий использования

1. Техник настраивает новый компьютер.
2. После завершения настройки вставляет USB-флешку.
3. Запускает `get-comp-info.bat`.
4. Скрипт автоматически собирает информацию о компьютере.
5. Скрипт отображает найденную информацию на экране.
6. Скрипт сохраняет информацию в JSON-файл на флешке.
7. Техник извлекает флешку и переходит к следующему компьютеру.
8. После обхода всех компьютеров содержимое флешки импортируется во внутреннюю систему.

Главная идея проекта:

> Вставил флешку → запустил скрипт → получил JSON → перешел к следующему компьютеру.

# Архитектура

Проект состоит из двух основных файлов:

```text
USB:\
├── get-comp-info.bat
├── get-comp-info.ps1
└── data\
```

## get-comp-info.bat

Точка входа.

Отвечает только за:

- запуск PowerShell;
- настройку кодировки консоли;
- удержание окна терминала открытым после завершения работы.

Вся бизнес-логика должна находиться в PowerShell.

---

## get-comp-info.ps1

Основной исполняемый модуль.

Отвечает за:

- сбор информации о компьютере;
- отображение информации пользователю;
- формирование JSON;
- сохранение JSON на флешку;
- проверку существующих файлов;
- запрос подтверждения перед перезаписью.

---

Информация хранится в формате JSON.

Пример:

```json
{
  "schemaVersion": 1,
  "hostname": "PC-0042",
  "serial": "PF58Y8F9",
  "manufacturer": "LENOVO",
  "model": "82YU",
  "network": {
    "ip": "192.168.1.167",
    "mac": "00-11-22-33-44-55"
  },
  "user": "OFFICE\\user",
  "windows": "Microsoft Windows 11 Pro",
  "collectedAt": "2026-08-21T16:20:31+03:00"
}
```
  "comment": "Заметка техника по этому компьютеру",

# Идентификатор компьютера

Основным идентификатором компьютера считается:

```text
serial
```

Файл сохраняется под именем серийного номера:

```text
data/PF58Y8F9.json
```

Причины:

- hostname может быть изменен;
- серийный номер обычно не меняется;
- удобно искать компьютер в базе данных;
- удобно предотвращать создание дубликатов.

---

# Поведение при существующем файле

Если файл с таким серийным номером уже существует:

1. Скрипт показывает предупреждение.
2. Скрипт показывает путь к существующему файлу.
3. Пользователь должен подтвердить перезапись.

Пример:

```text
WARNING!
File already exists:

D:\data\PF58Y8F9.json

Overwrite existing file? (Y/N)
```

Без подтверждения существующий файл не перезаписывается.

---

# Почему выбран JSON

Рассматривались следующие форматы:

- TXT
- CSV
- JSON

Выбран JSON по следующим причинам:

- легко обрабатывается в Node.js;
- поддерживает вложенные структуры;
- легко расширяется;
- хорошо подходит для API и баз данных;
- удобен для хранения инвентаризационных данных.

# Будущая интеграция

Утилита не должна напрямую обращаться к серверу или базе данных.

Она должна выполнять только одну задачу:

```text
Компьютер
    ↓
PowerShell
    ↓
JSON
    ↓
USB-флешка
```

Дальнейшая обработка выполняется отдельной системой:

```text
USB-флешка
    ↓
Импорт
    ↓
Node.js
    ↓
База данных
    ↓
Система заявок
```

# Требования к проекту

## Portable

Не должно требоваться:

- установка программы;

- изменение системных настроек;

# Основной принцип проекта

Утилита должна оставаться максимально простой.

Она не является системой учета.

Она не является агентом.

Она не является сервисом.

Ее единственная задача:

Собрать информацию о компьютере и сохранить её в структурированном виде для последующего импорта во внутреннюю систему.
