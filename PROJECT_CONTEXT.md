# Computer Inventory Collector

## Назначение проекта

Computer Inventory Collector — portable-утилита для сбора информации о компьютерах во время их подготовки и выдачи сотрудникам, и закрытая облачная база, в которой эта информация хранится.

Проект состоит из двух частей:

1. **Консольная утилита** (PowerShell) — запускается с USB-флешки или с компьютера техника, собирает данные о компьютере, хранит локальную копию базы и синхронизирует её с облаком.
2. **Облако** (Cloudflare) — основная база устройств с историей изменений, API для консольной утилиты и веб-интерфейс с разграничением доступа.

Главная идея:

> Вставил флешку → запустил скрипт → данные сохранены локально → при доступе в интернет синхронизировал с облаком.

---

# Источник истины

**Облако — основной источник данных.** Флешка и компьютер техника хранят вторичные локальные копии.

- Любая локальная копия (флешка или компьютер) синхронизируется только с облаком.
- Прямой синхронизации между флешкой и компьютером нет. Если данные с флешки нужны на компьютере, они проходят через облако в два этапа: флешка → облако → компьютер.
- Первичная загрузка существующих данных в облако — это обычная синхронизация с любой локальной копии. Неважно, запущена она с флешки или с компьютера.
- Сбор данных работает без интернета. Синхронизация выполняется позже, на любом компьютере с доступом в интернет.

Подробности: [CLOUD_SYNC.md](CLOUD_SYNC.md) — синхронизация из консоли, [CLOUD.md](CLOUD.md) — облако, API, веб-интерфейс и уровни доступа.

---

# Основной сценарий использования

1. Техник настраивает новый компьютер (интернет на нём может отсутствовать).
2. Вставляет USB-флешку и запускает `comp-info-menu.BAT` → «Собрать информацию о компьютере».
3. Скрипт собирает информацию, сравнивает её с локальной копией записи (если она есть) и сохраняет JSON в `data` на флешке.
4. Техник переходит к следующему компьютеру.
5. На любом компьютере с интернетом техник запускает «Синхронизировать с облаком» прямо с флешки.
6. Новые и изменённые записи отправляются в облако, а флешка получает актуальную копию всей базы для локального просмотра.
7. Коллеги видят данные в веб-интерфейсе согласно своим правам.

## Консольная утилита

Структура папки программы (одинаковая на флешке и на компьютере):

```text
COMP-INFO\
├── comp-info-menu.BAT       точка входа, главное меню
├── *.ps1, *.BAT             сценарии
├── cloud-config.json        адрес API (не секрет, хранится в Git)
├── cloud-key.txt            личный ключ доступа (необязательно, исключён из Git)
├── cloud-state.json         состояние синхронизации этой копии (исключён из Git)
├── network-profiles.json    кеш сетевых профилей из облака для настройки LAN (исключён из Git)
├── .update\                 загрузки и резервные копии обновлений программы (исключена из Git)
└── data\                    локальная копия записей, один JSON на устройство
```

- BAT-файлы отвечают только за запуск PowerShell, настройку кодировки и окна.
- Вся логика находится в PowerShell.
- `get-comp-info.ps1` собирает данные и сохраняет запись в локальный `data`. Сам он с сетью не работает.
- С облаком работают только `sync-cloud.ps1` (данные) и `update-program.ps1` (новые версии программы). Общий код для обоих — в `cloud-client.ps1`.
- `view-comp-info.ps1` показывает локальную копию, включая статус записи относительно облака.

## Облако

Cloudflare Workers (API и раздача веб-интерфейса), база Cloudflare D1, вход в веб-интерфейс через Cloudflare Access. Подробнее в [CLOUD.md](CLOUD.md).

# Формат данных

Каждая запись — JSON-объект. Пример:

```json
{
  "computerId": "03341FE8-9B79-4CC9-8CBD-A82BDD18C277",
  "computerIdSource": "smbiosUuid",
  "hostname": "PC-0042",
  "ip": "192.168.1.167",
  "mac": "00-11-22-33-44-55",
  "serial": "PF58Y8F9",
  "smbiosUuid": "03341FE8-9B79-4CC9-8CBD-A82BDD18C277",
  "manufacturer": "LENOVO",
  "model": "82YU",
  "username": "user",
  "comment": "Заметка техника по этому компьютеру",
  "windows": "Microsoft Windows 11 Pro",
  "esetInstalled": true,
  "collectedAt": "2026-08-21T16:20:31.0000000+03:00",
  "createdAt": "2026-08-20T10:02:11.0000000+03:00"
}
```

Поля:

- `computerId`, `computerIdSource` — идентификатор устройства и его источник (см. ниже);
- `hostname`, `serial`, `smbiosUuid`, `manufacturer`, `model` — идентификация компьютера;
- `ip`, `mac` — сеть;
- `username` — текущий пользователь Windows;
- `comment` — заметка техника;
- `windows` — версия Windows;
- `esetInstalled` — наличие антивируса ESET ([ESET_CHECK.md](ESET_CHECK.md));
- `collectedAt` — дата последнего сбора, `createdAt` — дата первого сохранения.

Служебные данные синхронизации (ревизия, кто и когда изменил запись в облаке) **не записываются** в JSON устройства. Они хранятся в облаке и в `cloud-state.json`.

Поля `addedToExternalDatabase` и `addedToExternalDatabaseAt` устарели. Раньше это была ручная отметка «добавлено во внешнюю базу». Теперь статус «есть в облаке» вычисляется автоматически (см. [CLOUD_SYNC.md](CLOUD_SYNC.md)), поэтому старые отметки сбрасываются: при синхронизации эти поля удаляются из записи и не попадают в облако.

# Идентификатор компьютера

Основной идентификатор — `computerId`, который выбирается по приоритету:

1. `smbiosUuid` — UUID материнской платы, если он корректен (не нулевой и не `FFFFFFFF-…`);
2. `serial` — серийный номер, если он пригоден (не пустой и не заглушка производителя);
3. `hostname` — в крайнем случае.

Файл записи называется `<computerId>.json` (недопустимые для имени файла символы заменяются на `_`).

Старые записи могли называться по серийному номеру и не содержать `computerId`. Для них идентификатором в облаке служит имя файла без `.json`. При повторном сборе на том же компьютере скрипт находит старый файл по серийному номеру и обновляет его.

`computerId` — ключ записи в облаке. Две записи с одинаковым `computerId` считаются одним устройством.

---

# Поведение при существующей записи

Если запись для этого компьютера уже есть в локальной копии:

1. Скрипт показывает таблицу сравнения «было / стало».
2. Если изменений нет, ничего не сохраняется.
3. Если изменения есть, пользователь должен подтвердить перезапись.

Локальная копия после синхронизации совпадает с облаком, поэтому сравнение идёт с последней известной облачной версией. Если локальная копия устарела (облако изменили после последней синхронизации), расхождение будет обнаружено и разобрано при следующей синхронизации.

# Требования к консольной утилите

## Portable

Не должно требоваться:

- установка программы;
- установка службы;
- изменение системных настроек;
- запись файлов на системный диск (кроме случая, когда программа сама лежит на компьютере);
- установка дополнительных модулей.

Всё должно работать непосредственно с USB-флешки.

## Независимость от буквы диска

Запрещено использовать фиксированные пути вида `D:\`, `E:\`, `F:\`.

Необходимо использовать:

- в BAT — `%~dp0`;
- в PowerShell — `$PSScriptRoot`.

## Работа без интернета

Сбор, просмотр, экспорт и все сетевые утилиты (LAN, ping) работают без интернета и без облака. Интернет нужен только для синхронизации.

## Совместимость

Целевые платформы:

- Windows 10;
- Windows 11.

Только встроенные возможности Windows: Windows PowerShell 5.1, CIM, WMI, `Invoke-RestMethod`. Без сторонних зависимостей.

## Безопасность

- Данные закрытые: в облаке они доступны только авторизованным пользователям.
- Консоль обращается к облаку только по HTTPS с личным ключом доступа.
- Ключ не хранится в Git. Если флешка с файлом ключа потеряна, ключ отзывают в веб-интерфейсе.

# Основной принцип проекта

Консольная утилита должна оставаться максимально простой.

Она не является агентом и не является сервисом: она ничего не делает в фоне и не устанавливается.

Её задачи:

1. Собрать информацию о компьютере и сохранить её локально, даже без интернета.
2. По команде пользователя синхронизировать локальную копию с облаком.

Учёт, история, поиск для всей команды и разграничение доступа — задачи облака.
