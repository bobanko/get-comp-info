# Имя компьютера и домен

В главном меню доступны «Имя компьютера (IF / FR)» и «Домен: ввод / вывод».
Операции выполняются на компьютере, где запущена программа. Если главное меню уже
работает с правами администратора, мастер открывается в том же окне. Иначе после
подтверждения UAC вся программа переходит в новое окно администратора: выбранный
мастер открывается автоматически, после него главное меню остаётся в новом окне.
Старое меню завершает работу только после успешного запуска нового; при отмене UAC
оно остаётся доступным. Запущенное через штатный BAT-лаунчер старое окно закрывается.
Если меню открыто в Windows Terminal, окно администратора тоже открывается через
`wt.exe` (чёрный фон, цветные эмодзи): обычный запуск `powershell.exe` с повышением
прав Windows открывает в старой консоли conhost с синим фоном и монохромными эмодзи.
При прямом запуске отдельного PS1 мастер ожидает завершения своего окна администратора.
Настройка LAN остаётся самостоятельной операцией.

## Правила имени

Конфигурация подразделения находится в [computer-policy.ps1](computer-policy.ps1) (оконная версия — `ComputerPolicy`
в `app\src\SystemChanges.cs`): номер `042` хранится строкой, рабочая группа — `WORKGROUP`,
префиксы — `IF` для интернета и `FR` для локальной доменной сети.
Имя домена в публичном репозитории не хранится: его задают в веб-интерфейсе на странице «Сеть», поле «Домен»
(если поле пустое, берётся «Проверка домена», если это не IP-адрес). Синхронизация и обновление программы
сохраняют его в `network-profiles.json`; без этого кэша ввод и вывод из домена недоступны.
Поддерживаются префиксы из двух или трёх заглавных латинских букв и трёхзначный номер части.
В другой части конфигурацию меняют при подготовке её копии программы. Обновление программы
заменяет этот файл: настройки другой части нужно включать в её выпуск.

Полное имя ограничено 15 символами. Окончание обязательно и содержит заглавную латиницу,
цифры и дефисы, без дефиса по краям. Для текущих префиксов остаётся восемь символов.
Например: `FR-042-TOC3`, `IF-042-PETRENKO`.

Мастер сохраняет окончание текущего имени, если оно имеет вид `XX-000-...` или
`XXX-000-...`. Иначе предлагает последние два октета первого подходящего IPv4-адреса
через дефис, например `FR-042-213-251`; без адреса предлагает `FR-042-PC`.
Техник редактирует окончание, указывая фамилию или отдел с номером. Кириллица
транслитерируется, пробелы превращаются в дефисы. Итоговое имя показывается перед
применением. Слишком длинный предложенный вариант сокращается; слишком длинный
ручной ввод требует исправления. Учётная запись техника не считается фамилией получателя.
Префикс обозначает назначение сети, фактическое членство в домене отображается отдельно.

## Ввод в домен

В оконной версии (`comp-info.exe`, раздел «Домен»):

1. Пока есть интернет, нажмите «Синхронизировать базу»: свободный адрес выбирается по локальной копии
   базы, и без синхронизации программа не видит адреса, выданные коллегами. Если синхронизации не было
   больше 12 часов, строка «База» подсвечена.
2. Имя сразу предлагается с префиксом `FR-042-`, окончание текущего имени сохраняется (`IF-042-BOB` → `FR-042-BOB`).
3. Выберите проводной адаптер, корпус и сегмент. Программа подставит первый адрес диапазона корпуса,
   которого нет ни в одной записи базы (запись этого компьютера не считается). Если на адаптере уже стоит
   адрес корпуса и в базе он ни за кем не числится, он остаётся. «Следующий свободный» перебирает адреса
   по кругу; рядом видно, свободен адрес или кем занят. Пункт «— не менять настройки сети» оставляет
   сеть как есть (например, если её настроили вручную в «Настройке сети»).
4. Введите только доменную учётную запись с правом ввода компьютера. Проверьте сводку и примените.
5. Программа назначает адрес, маску, шлюз и DNS корпуса (если они ещё не такие) и ждёт проверки
   дубликата адреса Windows. Если адрес уже занят в сети устройством, которого нет в базе, ввод
   останавливается, адрес запоминается как занятый и предлагается следующий свободный.
6. Затем DNS SRV и поиск контроллера через `nltest` (сразу после смены адреса — до четырёх попыток
   с паузой) и `Add-Computer` с новым именем.
7. Перезагрузите компьютер и повторно откройте раздел для проверки имени, членства
   и доверительного канала с доменом. Затем синхронизируйте базу: новый адрес попадёт в облако,
   и коллеги его не выдадут.

## Запись в локальной базе после изменения

Оконная версия сама сохраняет запись этого компьютера в `data`, отдельный «Сбор информации» не нужен:

- сразу после того, как Windows подтвердила переименование, ввод или вывод из домена, — с ожидаемыми
  после перезагрузки значениями: новое имя, членство в домене и домен / `WORKGROUP`, назначенный адрес
  при вводе. После перехода на DHCP прежний статический адрес в запись не попадает (адрес будет `null`,
  пока роутер не выдал новый), и в базе он освобождается;
- после «Применить» в «Настройке сети» — с новым статическим адресом (или без прежнего при DHCP);
- после перезагрузки, когда раздел подтвердил изменение, — ещё раз, уже по фактическому состоянию.

Остальные поля берутся с компьютера как при обычном сборе. Комментарий и пользователь из прежней записи
сохраняются: окно администратора может работать под другой учётной записью. Если есть старая запись
без устойчивого ID, которую нужно подтвердить, запись не сохраняется — программа напишет об этом,
и её нужно подтвердить в «Сборе информации». Синхронизация с облаком по-прежнему запускается вручную.

В консольной версии сеть настраивается отдельно: настройте LAN и DNS, затем в «Домен: ввод / вывод»
выберите ввод, задайте имя с `FR-042-` и введите доменную учётную запись.

Переименование и ввод выполняются одной командой `Add-Computer -NewName`, если имя
нужно изменить. Редакции Home, контроллеры домена и автоматический перенос из другого
домена не поддерживаются. OU и конкретный контроллер не задаются: используется стандартное
размещение домена. Права на существующий объект компьютера проверяет Windows;
программа не удаляет и не перезаписывает чужие объекты AD принудительно.

## Вывод из домена

### Оконная версия

Нужна только учётная запись локального администратора, доменная не спрашивается. Поле заполняется
само: текущий пользователь, если это локальный администратор (например, учётная запись, введённая
в окне UAC), иначе первый включённый пользователь, непосредственно входящий в группу администраторов
(встроенный `Administrator` — в последнюю очередь). Остаётся ввести пароль.

Компьютер выходит из домена локально: `Win32_ComputerSystem.UnjoinDomainOrWorkgroup` с
`FUnjoinOptions = 0`, затем `JoinDomainOrWorkgroup` в `WORKGROUP`. Контроллер домена не нужен,
объект компьютера в Active Directory не отключается и не удаляется — при повторном вводе с тем же
именем Windows использует его снова, а лишние объекты администратор домена удаляет сам.

По умолчанию отмечено (можно снять):

- «Сменить префикс на IF» — имя меняется на `IF-042-…` с тем же окончанием (`SetComputerNameEx`,
  локально, после выхода из домена);
- «Переключить на DHCP» — все физические адаптеры со статическим IPv4 или вручную заданными DNS
  переходят на автоматическую настройку, как пункт «Интернет — автоматически (DHCP)» в «Настройке сети».
  Компьютер уже выведен из домена, поэтому ошибка на этом шаге показывается предупреждением.

Ожидаемое после перезагрузки состояние (новое имя, `WORKGROUP`) записывается до команды Windows.

### Консольная версия

Перед выходом программа проверяет включённую локальную учётную запись,
непосредственно входящую в группу администраторов. Через Windows `LogonUser` проверяются
пароль и право интерактивного входа. Формат имени: `.\пользователь` или `ИМЯ-ПК\пользователь`.
Вложенные группы для этой проверки не используются. Затем нужны доменные учётные данные
с правом вывода и доступный контроллер домена.

Компьютер выводится в `WORKGROUP`, имя сохраняется. Доменные профили не преобразуются
в локальные. Для перевода в интернет после перезагрузки отдельно выберите имя с `IF`;
окончание будет сохранено. Доменные компьютеры нельзя переименовать с префиксом `IF`,
пока они не выведены из домена.

## Незавершённые операции

Перед системной командой записывается ожидаемое состояние в
`HKLM\SYSTEM\CurrentControlSet\Control\ComputerInventoryCollector\PendingChange`.
Пароли и имена учётных записей туда не записываются. Это единственная служебная запись
нового мастера вне каталога программы; она доступна любой копии программы на этом ПК.
Повторные изменения блокируются до перезагрузки. Также проверяются ожидающее
переименование Windows и маркеры Netlogon.

Перезагрузка выполняется только при выборе «Перезагрузить сейчас».
При ошибке Windows возможен частичный результат: автоматического отката нет.
После перезагрузки мастер сравнивает фактическое и ожидаемое состояние и проверяет
доверительный канал для доменного компьютера. Несовпадение или недоступность домена
показываются отдельно; сброс блокировки требует явного подтверждения просмотра результата.
Автозапуск после перезагрузки и фоновая служба не устанавливаются.

## Устойчивый ID инвентаризации

Новые записи используют UUID SMBIOS, пригодный серийный номер или, последним резервом,
`WINDOWS-<MachineGuid>`. Идентификатор установки Windows читается из 64-битного представления
реестра на 64-битной Windows и сохраняется в `windowsMachineGuid`. Он переживает
переименование и сбор с другой флешки, но может измениться после переустановки ОС.
Некорректно клонированные установки могут иметь одинаковый MachineGuid; такие записи
требуют проверки, особенно если отсутствуют аппаратные идентификаторы.

Существующие записи ищутся по устойчивым идентификаторам. Их облачный ключ и имя файла
сохраняются: старый ключ может исторически совпадать с прежним hostname, но больше
не вычисляется из имени компьютера (`computerIdSource = legacyId`). Это сохраняет историю
и предотвращает дубликаты при переименовании. Несколько подходящих записей требуют
ручного устранения неоднозначности.

Если старая запись не имеет аппаратных ID или MachineGuid, совпадение имени даёт только
кандидата для ручного подтверждения. Сначала выполните сбор и подтвердите привязку;
до этого мастер не разрешает переименование. После сохранения запись находится по
MachineGuid. Для старых записей используйте предварительно синхронизированную копию
базы; отсутствующую на флешке запись программа обнаружить не может.

Сбор также сохраняет фактические `partOfDomain` и `domain`. Пароли не сохраняются
в JSON, реестре, аргументах процессов и облаке. Мастер не синхронизирует базу с облаком
(запись в локальной базе оконная версия обновляет сама, см. выше; консольная — нет).

## Проверка

Тесты `tests/computer-*.tests.ps1` проверяют имена, идентификацию, миграцию старых ключей,
порядок проверок, ошибки, локальный вход, UAC и состояние после перезагрузки.
Системные команды, реестр, CIM и нативный вход заменены тестовыми реализациями.
Проверка на настоящем домене требует отдельного тестового компьютера: ввод,
перезагрузка, проверка доверия, доменное переименование, вывод, локальный вход,
перезагрузка и назначение имени `IF`.
