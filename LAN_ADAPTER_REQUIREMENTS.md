# Настройка адаптера локальной сети

## Задача

Переносимый PowerShell-скрипт `setup-lan-adapter.ps1` запускается с флешки на компьютере в одном из корпусов и настраивает выбранный сетевой адаптер под выбранный корпус и сегмент сети.

## Откуда берутся настройки корпусов

Адреса сетей в репозитории не хранятся. Корпуса, подсети, шлюзы, диапазоны адресов и DNS задаёт администратор на странице «Сеть» веб-интерфейса облака ([CLOUD.md](CLOUD.md)). Синхронизация с облаком ([CLOUD_SYNC.md](CLOUD_SYNC.md)) сохраняет их в `network-profiles.json` в папке программы (файл исключён из Git), и дальше настройка работает без интернета.

Если кеша ещё нет (программу ни разу не синхронизировали), в меню доступна только автоматическая настройка (DHCP) и показывается подсказка синхронизироваться.

Что задаётся в облаке:

- **первый октет** всех сетей;
- **сегменты** — варианты второго октета; первый предлагается по умолчанию;
- **узел для проверки домена** — его пингует быстрый ping (`quick-ping.ps1`), если адрес компьютера входит в одну из сетей; если не задан, проверяется доступ в интернет;
- для каждого **корпуса**: название, третий октет, длина префикса (маска вычисляется из неё), последний октет шлюза, первый и последний допустимый адрес компьютера, 1–4 DNS-сервера и, при необходимости, свои сегменты вместо общих.

Облако проверяет, что шлюз и диапазон адресов лежат в одной подсети, не включают адрес сети, широковещательный адрес и сам шлюз.

Пример (вымышленные адреса): первый октет `10`, сегменты `20, 21`, корпус «Главный» с третьим октетом `5`, префиксом `/25`, шлюзом `129` и адресами `130–254`. Для сегмента `20` компьютер получит адрес `10.20.5.<130–254>`, маску `255.255.255.128`, шлюз `10.20.5.129`; для сегмента `21` меняется только второй октет.

## Требования к работе скрипта

1. Показать оператору список корпусов из кеша и пункт автоматической настройки (DHCP).
2. Предложить выбрать сегмент сети (общие сегменты или свои сегменты корпуса).
3. Показать доступные сетевые адаптеры и позволить выбрать нужный.
4. Запросить последний октет статического IP-адреса и проверить, что он входит в диапазон корпуса.
5. Перед применением вывести сводку: корпус, адаптер, IP, маску, шлюз и DNS; запросить подтверждение.
6. Удалить прежние IPv4-адреса и маршруты по умолчанию только у выбранного адаптера.
7. Установить новые статические IPv4-настройки и DNS-серверы.
8. При запуске без прав администратора автоматически запросить повышение прав через UAC и перезапустить себя с правами администратора.
9. Вывести итоговую конфигурацию после успешного применения.

## Автоматическая настройка для интернета (DHCP)

На первом экране доступен пункт «Интернет — автоматически (DHCP), сброс IP, шлюза и DNS».
После него оператор выбирает проводной адаптер и подтверждает сводку; корпус, сегмент и IP вводить не нужно.
`Esc` возвращает к выбору адаптера, а при единственном адаптере — к выбору сети.

Скрипт включает выбранный адаптер, если он отключён, удаляет его статические IPv4-адреса и статические маршруты по умолчанию из сохранённой и активной конфигурации, включает DHCP и сбрасывает вручную заданные DNS-серверы на автоматические.
Другие адаптеры не изменяются. Для применения используются те же права администратора через UAC, что и при статической настройке.
После применения выводится текущая конфигурация; получение адреса, шлюза и DNS от роутера может занять некоторое время.

## Файлы

- `setup-lan-adapter.ps1` — основной скрипт настройки.
- `lan-profiles.ps1` — чтение кеша профилей `network-profiles.json` и проверка «адрес из наших сетей» для быстрого ping.
- `scan-ips.ps1` — черновик: какие адреса подсети заняты (подсеть спрашивается при запуске).

Проверки без изменения сети: `tests/lan-dhcp.tests.ps1`, `tests/lan-profiles.tests.ps1`.
