# Облако: база, API и веб-интерфейс

> Статус: работает на https://comp-info.chagear.top.

Облако — основной источник данных об устройствах. Оно хранит актуальные записи и полную историю изменений, принимает синхронизацию из консольной утилиты ([CLOUD_SYNC.md](CLOUD_SYNC.md)) и даёт закрытый веб-интерфейс с разграничением доступа.

## Стек

| Часть | Технология |
|---|---|
| API и раздача веб-интерфейса | Cloudflare Workers (TypeScript) со статическими ассетами |
| База | Cloudflare D1 (SQLite) |
| Вход в веб-интерфейс | Cloudflare Access (вход по коду на почту для разрешённых адресов) |
| Доступ из консоли | Личные ключи, проверяет Worker |
| Публикация версий программы | GitHub Actions по тегу → `POST /api/release` ([PROGRAM_UPDATE.md](PROGRAM_UPDATE.md)) |

Ожидаемая нагрузка: 5–10 пользователей, сотни записей, синхронизация примерно раз в день. Это далеко в пределах бесплатных тарифов Cloudflare. Актуальные лимиты сверяются при развёртывании.

Код облака лежит в папке `cloud/` этого репозитория. Это отдельный проект на Node.js: Worker, веб-интерфейс, миграции D1 и тесты. На флешку он не копируется.

## Модель данных

Запись устройства хранится как JSON целиком, в том же формате, что и в консоли ([PROJECT_CONTEXT.md](PROJECT_CONTEXT.md)). Поэтому новые поля сбора не требуют изменения схемы базы. Служебные данные хранятся рядом с записью, а не внутри неё.

```sql
-- Текущее состояние устройств
devices (
  id            TEXT PRIMARY KEY,  -- computerId
  data          TEXT NOT NULL,     -- JSON записи
  revision      INTEGER NOT NULL,  -- 1, 2, 3… растёт при каждом изменении
  change_id     INTEGER NOT NULL,  -- id последней строки в device_history (для загрузки изменений)
  created_at    TEXT NOT NULL,
  updated_at    TEXT NOT NULL,
  updated_by    TEXT NOT NULL,     -- email пользователя
  deleted_at    TEXT               -- не NULL — запись удалена (мягкое удаление)
)

-- Полная история: каждая версия каждой записи
device_history (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  device_id     TEXT NOT NULL,
  revision      INTEGER NOT NULL,
  action        TEXT NOT NULL,     -- create | update | delete | restore
  data          TEXT NOT NULL,     -- JSON записи в этой ревизии
  changed_at    TEXT NOT NULL,
  changed_by    TEXT NOT NULL,
  source        TEXT NOT NULL      -- console | web
)

users (
  email         TEXT PRIMARY KEY,
  name          TEXT NOT NULL,
  role          TEXT NOT NULL,     -- viewer | harvester | editor | admin
  active        INTEGER NOT NULL,
  created_at    TEXT NOT NULL
)

access_requests (                 -- вошли через Access, но ещё не пользователи
  email         TEXT PRIMARY KEY,
  requested_at  TEXT NOT NULL,
  last_seen_at  TEXT NOT NULL,
  rejected_at   TEXT,              -- отклонён администратором
  rejected_by   TEXT
)

api_keys (
  id            TEXT PRIMARY KEY,
  user_email    TEXT NOT NULL,
  label         TEXT NOT NULL,     -- например, «Флешка Сергея»
  key_hash      TEXT NOT NULL,     -- SHA-256 ключа; сам ключ не хранится
  created_at    TEXT NOT NULL,
  last_used_at  TEXT,
  revoked_at    TEXT
)

-- Версии консольной программы
program_releases (
  version       TEXT PRIMARY KEY,  -- 2026.10.23.1
  commit_sha    TEXT NOT NULL,
  manifest      TEXT NOT NULL,     -- manifest.json
  package       BLOB NOT NULL,     -- zip, не больше 1 МБ
  sha256        TEXT NOT NULL,
  size          INTEGER NOT NULL,
  published_at  TEXT NOT NULL,
  is_current    INTEGER NOT NULL   -- ровно одна версия текущая
)

-- Общие настройки, сейчас одна: 'network' — сетевые профили для настройки LAN в консоли
settings (
  key           TEXT PRIMARY KEY,
  value         TEXT NOT NULL,     -- JSON
  revision      INTEGER NOT NULL,
  updated_at    TEXT NOT NULL,
  updated_by    TEXT NOT NULL
)

settings_history (                 -- каждая сохранённая версия настройки
  id, key, revision, value, changed_at, changed_by   -- UNIQUE (key, revision)
)
```

### Сетевые профили

Адреса внутренних сетей хранятся только здесь, чтобы репозиторий можно было открыть. Документ `network`:

```json
{
  "firstOctet": 10,
  "segments": [20, 21],
  "domainCheckHost": "dc.example.local",
  "locations": [
    { "name": "Главный корпус", "thirdOctet": 5, "prefixLength": 25, "gatewayOctet": 129,
      "firstHostOctet": 130, "lastHostOctet": 254, "dnsServers": ["10.9.0.1"], "segments": [20] }
  ]
}
```

Значения в примере вымышленные. При сохранении Worker проверяет: октеты 0–255, префикс 24–30, шлюз и диапазон адресов внутри одной подсети без адреса сети, широковещательного адреса и самого шлюза, 1–4 DNS-сервера IPv4, уникальные названия корпусов, сегменты без повторов. `segments` у корпуса необязательны (по умолчанию общие). Лишние поля отбрасываются. Смысл полей — в [LAN_ADAPTER_REQUIREMENTS.md](LAN_ADAPTER_REQUIREMENTS.md).

Правила:

- Изменение записи и запись в `device_history` выполняются одним пакетом D1, то есть атомарно.
- Если новое содержимое совпадает со старым (без учёта порядка ключей и форматирования), новая ревизия не создаётся.
- Удаление мягкое: запись помечается `deleted_at`, история сохраняется, восстановление возможно.
- Устаревшие поля `addedToExternalDatabase` и `addedToExternalDatabaseAt` удаляются из входящих данных.
- Входящие данные проверяются: JSON-объект, размер не больше 64 КБ, `computerId` внутри записи (если есть) совпадает с `id`.

Резервное копирование: встроенное восстановление D1 на момент времени (Time Travel) и периодический экспорт базы. Детали настраиваются при развёртывании.

## Уровни доступа

Четыре роли, каждая следующая включает права предыдущей:

- **viewer** — только веб-интерфейс, только просмотр. С консолью и флешкой не работает, ключей не имеет.
- **harvester** — сборщик: ходит с флешкой, собирает данные и синхронизирует их с облаком. В вебе только просматривает.
- **editor** — дополнительно редактирует записи в веб-интерфейсе.
- **admin** — дополнительно управляет пользователями и ролями, ключами всех пользователей, удаляет и восстанавливает записи.

| Действие | viewer | harvester | editor | admin |
|---|:-:|:-:|:-:|:-:|
| Веб: таблица, карточки, поиск, сортировка, история | ✓ | ✓ | ✓ | ✓ |
| Веб: экспорт CSV | ✓ | ✓ | ✓ | ✓ |
| Свои личные ключи: создать, отозвать | | ✓ | ✓ | ✓ |
| Консоль: синхронизация (отправка и загрузка базы) | | ✓ | ✓ | ✓ |
| Консоль: обновление программы | | ✓ | ✓ | ✓ |
| Веб: редактирование записей | | | ✓ | ✓ |
| Веб: удаление и восстановление записей | | | | ✓ |
| Веб: пользователи, роли, ключи всех пользователей | | | | ✓ |

Права ключа равны текущим правам его владельца. Если роль пользователя изменить или отключить его, это сразу действует и на все его ключи. Если понизить роль до `viewer`, все ключи пользователя перестают работать (сами ключи не удаляются, чтобы их можно было вернуть при повышении роли).

## Аутентификация

### Веб-интерфейс

Весь веб-интерфейс и веб-API (`/api/web/*`) закрыты Cloudflare Access: войти можно, только получив одноразовый код на почту. Код выдаётся на любую почту (политика «Comp Info team» — Include: Everyone), поэтому Access подтверждает лишь владение почтой, а кого пускать, решает Worker. Он проверяет подпись Access-токена (заголовок `Cf-Access-Jwt-Assertion`), берёт из него email и находит роль в таблице `users`.

Если почты нет в `users`, Worker записывает запрос в `access_requests` и отвечает 403 `access_pending`: человек видит «Запрос отправлен», а администратор — запрос на странице «Пользователи» (и счётчик в меню). Администратор пускает его (выбирает имя и роль — пользователь создаётся, запрос удаляется) или отклоняет (дальше 403 `access_denied`, пока его не добавят вручную). Отключённый пользователь получает 403 `user_disabled`. Ожидающих запросов хранится не больше 100. Первый `admin` создаётся командой при развёртывании ([cloud/README.md](cloud/README.md)).

### Консоль

Путь `/api/client/*` в Access исключён и проверяется Worker'ом по личному ключу: `Authorization: Bearer <ключ>`.

- Формат ключа: `ci_` и 32 случайных байта в base64url.
- Ключ показывается один раз при создании. В базе хранится только SHA-256.
- При каждом запросе обновляется `last_used_at`. Ответ на неверный или отозванный ключ — 401.
- Ключ владельца с ролью `viewer` или отключённого пользователя — 403.

## API для консоли (`/api/client`)

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/me` | Пользователь, роль, название ключа |
| `GET` | `/devices?since=<cursor>&limit=<n>` | Записи, изменённые после `cursor` (включая удалённые); при `since=0` вся база. Страница — до `limit` записей (по умолчанию 500, максимум 1000) |
| `PUT` | `/devices/{id}` | Создать или изменить запись |
| `GET` | `/program/latest` | Текущая версия программы: `version`, `sha256`, `size`, `publishedAt`, `notes` |
| `GET` | `/program/{version}/package` | Архив версии (zip) |
| `GET` | `/settings/network` | Сетевые профили для кеша консоли (404, если не заданы) |

`GET /devices` возвращает:

```json
{
  "cursor": 1842,
  "hasMore": false,
  "devices": [
    { "id": "…", "revision": 7, "deleted": false, "createdAt": "…", "updatedAt": "…", "updatedBy": "…", "data": { } }
  ]
}
```

Если `hasMore` равно `true`, консоль запрашивает следующую страницу с `since=<cursor>`. Последний `cursor` сохраняется в `cloud-state.json`.

`PUT /devices/{id}` принимает `{ "baseRevision": 6, "data": { }, "restore": false }`:

- `200 { "revision": 7, "changed": true, "device": { … } }` — принято. Если содержимое совпало с облачным, ответ `"changed": false`, и `baseRevision` в этом случае не проверяется;
- `409 { "error": { … }, "current": { "revision": 8, "updatedAt": "…", "updatedBy": "…", "data": { } } }` — конфликт: `baseRevision` не совпадает с текущей ревизией (для новой записи — запись уже существует с другим содержимым);
- `410 { "error": { … }, "current": { … } }` — запись удалена в облаке. Восстановить её можно повторным запросом с `"restore": true`;
- `400` / `413` — неверный запрос, несовпадение `computerId` с `id` или запись больше 64 КБ.

Ошибки всегда приходят в формате `{ "error": { "code": "…", "message": "…" } }`. Сообщение на русском, консоль может показывать его как есть.

Все методы `/api/client` доступны ролям `harvester`, `editor` и `admin`.

## Публикация версий (`/api/release`)

`POST /api/release` вызывается только из GitHub Actions. Авторизация — OIDC-токен запуска GitHub Actions (`Authorization: Bearer <token>`), общих секретов нет. Worker проверяет подпись токена ключами GitHub, издателя `https://token.actions.githubusercontent.com`, аудиторию `comp-info-release`, что `repository` равен `RELEASE_REPOSITORY` (`bobanko/get-comp-info`) и что запуск сделан по тегу. Личные ключи здесь не принимаются. Путь исключён из Cloudflare Access.

Тело запроса — zip-архив (`Content-Type: application/zip`) с `manifest.json` внутри. Worker проверяет:

- формат версии `ГГГГ.ММ.ДД.N` и что тег запуска равен `v<версия>`;
- что такой версии ещё нет (иначе 409);
- размер архива не больше 1 МБ (иначе 413);
- что каждый файл из манифеста есть в архиве и совпадает по размеру и SHA-256, имена — только файлы программы из корня, лишних файлов нет.

После этого версия сохраняется в `program_releases` и становится текущей одной атомарной операцией. Локальный сервер разработки (`localhost` с `DEV_AUTH_EMAIL`) принимает публикацию без токена. Порядок выпуска описан в [PROGRAM_UPDATE.md](PROGRAM_UPDATE.md).

## Веб-интерфейс

> Статус: реализовано (`cloud/public`).

Адрес: https://comp-info.chagear.top. Возможности те же, что в консольном просмотрщике, плюс то, чего в консоли нет. Светлая и тёмная тема по настройке системы, работает и на телефоне.

**Устройства**
- Колонки: имя компьютера, IP, пользователь, серийный номер, производитель и модель, ESET, дата сбора, комментарий; по желанию — Windows и «Изменено в облаке». Набор колонок и сортировка запоминаются в браузере.
- Поиск по всем полям (все слова запроса должны встретиться в записи), фильтр по ESET, «Повторяющиеся IP», сортировка по любой колонке (IP — как адрес, пустые значения всегда в конце).
- Подсветка: повторяющиеся IP — красным, сбор за последние 7 дней — зелёным, ESET — цветным бейджем.
- Экспорт CSV показанных записей в формате консольного экспорта ([CSV_EXPORT.md](CSV_EXPORT.md)).
- `admin` может включить показ удалённых записей.

**Карточка устройства**
- Все поля записи, ревизия, кто и когда изменил в облаке.
- История: список ревизий (кто, когда, откуда — консоль или веб); для выбранной ревизии — различия с предыдущей по полям.
- Правка (`editor`): имя компьютера, IP, MAC, серийный номер, производитель, модель, пользователь, Windows, комментарий. Идентификатор и даты сбора меняет только консоль. Отправляются только изменённые поля с `baseRevision`; если запись успели изменить, правки не сохраняются и показывается, что изменилось.
- Удаление и восстановление (`admin`).

**Мои ключи** (`harvester` и выше): создать ключ с названием (показывается один раз, с кнопкой копирования), видеть дату последнего использования, отозвать. `admin` видит ключи всех пользователей.

**Пользователи** (`admin`): запросы на доступ (пустить с именем и ролью или отклонить), добавление вручную, имя, роль, включение и отключение. Собственную роль и доступ изменить нельзя. Число ожидающих запросов видно в меню рядом с «Пользователи».

**Сеть** (`admin`): общая часть адреса (первый октет и сегменты — второй октет, узел для проверки домена) и таблица корпусов в порядке меню консоли: подсеть, шлюз, адреса ПК и DNS полными адресами. Нажатие на строку открывает редактор корпуса, где октеты вводятся прямо внутри адреса (`10.20.[128].x`). Диапазон адресов ПК по умолчанию считается сам по шлюзу и маске; его можно задать вручную. Ошибки показываются рядом с полями до сохранения, по тем же правилам, что проверяет сервер. Сохранение — с ревизией, как у записей устройств; история изменений свёрнута внизу.

**Версии программы** (`admin`): опубликованные версии с «Что нового», размером и коммитом; кнопка «Сделать текущей» для отката.

Истёкшая сессия Access распознаётся: страница предлагает обновиться и войти заново.
