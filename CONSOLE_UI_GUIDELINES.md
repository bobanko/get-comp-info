# Стиль консольных интерфейсов PowerShell

Этот документ задаёт общий стиль для интерактивных PowerShell-скриптов проекта.

## Основные принципы

- Интерфейс полностью на русском языке.
- Один экран должен показывать только информацию текущего шага.
- Длинные операции запускаются в фоне до момента, когда их результат понадобится пользователю.
- Для выбора использовать стрелки `Вверх`/`Вниз` и `Enter`, а не ручной ввод номера.
- `Esc` используется только для возврата на предыдущий шаг и никогда не закрывает окно или не отменяет скрипт.
- Если предыдущего шага нет, `Esc` оставляет пользователя на текущем экране.

## Структура экрана мастера

- Каждый экран начинается с общего хедера с названием программы, и названия текущего раздела. Использовать общую функцию `Write-ToolboxHeader` из `console-ui.ps1`, а не дублировать её реализацию в сценариях.
- Рядом с названием показывать версию серым: `vГГГГ.ММ.ДД.N`, где `N` — номер выпуска за день. Версия явно записана в `console-ui.ps1` и не зависит от дат файлов, пересылки, запуска или изменения данных компьютеров.
- Перед выпуском новой версии запустить `tools/update-version.BAT` (двойным кликом или из терминала), затем сохранить изменение `console-ui.ps1` в Git, поставить тег `vВЕРСИЯ` и отправить его в GitHub. GitHub Actions опубликует версию в облаке (если Actions недоступен — запустить `tools/release.BAT`), а пользователи установят её пунктом «Обновить программу» ([PROGRAM_UPDATE.md](PROGRAM_UPDATE.md)). Лаунчер открывает PowerShell с `ExecutionPolicy Bypass` только для этого процесса и оставляет окно открытым для просмотра результата или ошибки. Скрипт ставит текущую дату и увеличивает номер выпуска за тот же день; в новый день начинает с `1`. Обычный запуск и синхронизация версию не повышают. Папка `tools` предназначена для разработки и на флешку не копируется.

Каждый экран мастера строится в одинаковом порядке:

1. Первая строка — подсказка по управлению.
2. Вторая строка — номер шага, например `Шаг 2 из 5`.
3. Третья строка — краткое описание действия.
4. Пустая строка.
5. Элементы выбора, поле ввода или сводка.

Перед переходом между шагами экран очищается через `Clear-Host`. Это не относится к сообщениям об ошибке: они должны оставаться видимыми на экране повторного ввода.

## Навигация и ввод

- Все подсказки горячих клавиш выводить через общую функцию `Write-ToolboxHint` из `console-ui.ps1`: клавиши в квадратных скобках — `Yellow`, пояснения — `DarkGray`. Предупреждения и статусы выводить отдельно, сохраняя их смысловой цвет.

- В подсказках горячие клавиши всегда заключать в квадратные скобки: `[↲ Enter]`, `[Esc]`, `[▲▼]`, `[←→]`, `[A]`, `[F2]`, `[Backspace]`. Описание действия писать после тире; несколько сочетаний разделять пробелами.

- В меню выделять выбранный пункт указателем `>`.
- Номера пунктов допустимо показывать как ориентир, но не использовать как обязательный способ управления.
- Для текстового или числового ввода выводить приглашение на отдельной строке, например `> `.
- Поддерживать `Backspace` при ручном вводе.
- Горячие клавиши обрабатывать по физической клавише (`ConsoleKey` или `VirtualKeyCode`), а не по введённому символу (`KeyChar` или `Character`), чтобы они работали при любой раскладке. Это правило не относится к полям текстового ввода.
- При некорректном значении показывать короткое красное сообщение и повторять ввод на чистом экране.
- Если доступен единственный вариант, пропускать меню выбора и сообщать, какой вариант выбран автоматически.

## Цвета

- `Cyan` — основные параметры, которые будут применены или уже применены.
- `DarkGray` — контекст, метаданные, общие параметры и подсказки.
- `Green` — успешное состояние или включённый ресурс.
- `Yellow` / `DarkYellow` — предупреждение, неизвестное состояние или отсутствие подключения.
- `Red` — ошибка, отключённый ресурс либо недопустимый ввод.
- В строках со статусом окрашивать только статус, а не название ресурса. Например: `Ethernet [Включён]`, где название обычного цвета, а статус — зелёный.

## Подтверждение и сводка

- Перед необратимым действием показывать итоговую сводку отдельным последним шагом.
- В сводке выделять цветом только применяемые значения; корпус, сегмент, выбранный ресурс и прочий контекст оставлять второстепенным цветом.
- Повторяющиеся значения показывать отдельными строками, например `DNS 1` и `DNS 2`.
- `Enter` подтверждает действие. `Esc` возвращает к предыдущему редактируемому шагу, а не отменяет или закрывает скрипт.

## Кодировка и запуск

- PowerShell-скрипты с русским текстом и emoji сохранять в UTF-8 с BOM для совместимости с Windows PowerShell 5.1.
- В начале скрипта задавать UTF-8 для `[Console]::OutputEncoding` и `[Console]::InputEncoding`.
- Emoji добавлять через `[char]::ConvertFromUtf32(...)`, если важна совместимость со средами без UTF-8 BOM.
- BAT-лаунчер должен запускать PowerShell в отдельном окне и сразу завершаться, чтобы не оставлять пользователю лишнюю консоль `cmd`.
