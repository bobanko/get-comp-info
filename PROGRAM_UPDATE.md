# Обновление программы

> Статус: спецификация, реализация в работе. Заменяет обновление программы через `sync-usb.ps1` и `update-from-github.ps1`.

Новые версии программы распространяются через облако. Исходники лежат в приватном репозитории GitHub. GitHub Actions собирает из них архив версии и публикует его в облаке, а консоль скачивает архив по тому же личному ключу, что и для синхронизации ([CLOUD_SYNC.md](CLOUD_SYNC.md)).

Сборщикам не нужны ни доступ к GitHub, ни Git, ни отдельный токен. Обновление приходит только при выпуске версии, а не при каждом коммите.

```text
Разработчик                GitHub Actions                 Cloudflare                     Флешка / компьютер
update-version.BAT  ─►  тег vВЕРСИЯ  ─►  сборка архива  ─►  POST /api/release  ─►  D1  ─►  «Обновить программу»
коммит + тег + push        проверки, manifest.json           (токен публикации)            (личный ключ)
```

## Состав версии

В архив входят только файлы программы из корня репозитория:

- `*.ps1`, `*.BAT`, `*.cmd`;
- `cloud-config.json`;
- `manifest.json` — описание версии (создаётся при сборке).

Не входят: `data`, `exports`, документация, `tests`, `tools`, `cloud`, `.github`, `desktop.ini`, `.git`.

`manifest.json`:

```json
{
  "version": "2026.10.23.1",
  "commit": "7f7e177…",
  "publishedAt": "2026-10-23T14:05:12Z",
  "notes": ["fix: usb get proper serial, which matches with usd deview", "…"],
  "files": [
    { "path": "get-comp-info.ps1", "sha256": "…", "size": 15873 }
  ]
}
```

`notes` — заголовки коммитов с предыдущего тега. Консоль показывает их как «Что нового».

## Выпуск версии

1. Запустить `tools/update-version.BAT`, чтобы поднять `$script:toolboxVersion` в `console-ui.ps1`.
2. Закоммитить изменения.
3. Поставить тег с той же версией и отправить в GitHub:

   ```powershell
   git tag v2026.10.23.1
   git push origin main --tags
   ```

GitHub Actions (`.github/workflows/release.yml`) по тегу `v*`:

1. Проверяет, что тег совпадает с версией в `console-ui.ps1`, иначе выпуск останавливается.
2. Запускает тесты из `tests`.
3. Собирает архив и `manifest.json` с SHA-256 каждого файла.
4. Отправляет архив в облако: `POST /api/release` с токеном публикации из GitHub Secrets.

Облако сохраняет версию и делает её текущей. Повторно опубликовать ту же версию нельзя. Если выпуск сломан, выпустите следующую версию или откатите текущую в веб-интерфейсе.

## Обновление в консоли

Пункт главного меню «Обновить программу» или `update-program.BAT`. Работает в той копии программы, из которой запущен, то есть на флешке или на компьютере.

1. **Ключ** берётся так же, как при синхронизации: из `cloud-key.txt` или вводом с предложением сохранить.
2. **Проверка версии.** `GET /program/latest` возвращает текущую версию в облаке. Скрипт сравнивает её с `$script:toolboxVersion`:
   - версии совпадают — «Установлена последняя версия», больше ничего не делается;
   - в облаке новее — показываются обе версии и «Что нового»;
   - в облаке старее (администратор откатил выпуск) — предлагается откат до неё с явной пометкой.
3. **Подтверждение.** `Enter` устанавливает, `Esc` отменяет.
4. **Загрузка** в `.update\<версия>.zip` внутри папки программы, без записи на системный диск. Проверяются размер и SHA-256 архива.
5. **Распаковка и проверка.** Архив распаковывается в `.update\<версия>\`. Каждый файл сверяется с `manifest.json`. Пути допускаются только в корне программы (без подпапок и `..`). Любое расхождение останавливает обновление, и программа остаётся нетронутой.
6. **Резервная копия** текущих файлов программы сохраняется в `.update\backup-<текущая версия>\`.
7. **Замена.** Каждый файл записывается через временный файл с заменой и проверяется по SHA-256.
8. **Удаление устаревших файлов.** Файлы программы в корне (`*.ps1`, `*.BAT`, `*.cmd`), которых нет в новой версии, удаляются. Они остаются в резервной копии. Так с флешек исчезнут, например, `sync-usb.ps1` и `update-from-github.ps1`.
9. **Завершение.** Показывается «Программа обновлена до версии …», меню перезапускается уже с новой версией.

Если любой шаг 7–8 завершился ошибкой, файлы автоматически восстанавливаются из резервной копии. Если не удалось и это, на экране показывается путь к резервной копии для ручного восстановления. Код завершения при ошибке — 1.

Обновление **никогда не трогает**: `data`, `exports`, `cloud-key.txt`, `cloud-state.json`, `desktop.ini`, `.update` и любые подпапки. Собственные скрипты в корне папки программы держать нельзя: обновление удалит их как устаревшие (они останутся в резервной копии).

Хранятся только две последние резервные копии и архивы, более старые удаляются после успешного обновления.

### Ограничения

- Если в папке программы есть `.git`, это копия для разработки. Обновление отказывается работать и предлагает обновляться через Git.
- Перед обновлением закройте сборщик, просмотрщик и другие окна программы. Меню перезапускается само.
- Синхронизация с облаком тоже проверяет версию и в итоге показывает подсказку, если вышла новая.

## Облако

Подробности в [CLOUD.md](CLOUD.md):

- архивы версий хранятся в D1, в таблице `program_releases`. Размер архива ограничен 1 МБ, сейчас он около сотни килобайт;
- `GET /api/client/program/latest` и `GET /api/client/program/{version}/package` — для ролей `harvester`, `editor`, `admin`;
- `POST /api/release` — только с токеном публикации (секрет Worker'а и GitHub Secrets), не с личными ключами;
- в веб-интерфейсе `admin` видит список версий и может сделать текущей любую из них (откат).
