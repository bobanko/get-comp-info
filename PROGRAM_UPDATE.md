# Обновление программы

> Статус: реализовано (`update-program.ps1`, `tools/build-release.ps1`, `.github/workflows/release.yml`, `cloud/src/releases.ts`). Заменяет обновление через `sync-usb.ps1` и `update-from-github.ps1` — оба удалены.

Новые версии программы распространяются через облако. Исходники лежат в приватном репозитории GitHub. GitHub Actions собирает из них архив версии и публикует его в облаке, а консоль скачивает архив по тому же личному ключу, что и для синхронизации ([CLOUD_SYNC.md](CLOUD_SYNC.md)).

Сборщикам не нужны ни доступ к GitHub, ни Git, ни отдельный токен. Для публикации не нужны секреты: облако проверяет подписанный GitHub токен запуска (OIDC). Обновление приходит только при выпуске версии, а не при каждом коммите.

```text
Разработчик                GitHub Actions                       Cloudflare                     Флешка / компьютер
update-version.BAT  ─►  тег vВЕРСИЯ  ─►  тесты, сборка архива  ─►  POST /api/release  ─►  D1  ─►  «Обновить программу»
коммит + тег + push                       manifest.json            (OIDC-токен GitHub)             (личный ключ)
```

## Состав версии

В архив входят только отслеживаемые Git'ом файлы программы из корня репозитория:

- `*.ps1`, `*.BAT`, `*.cmd`;
- `cloud-config.json`;
- `manifest.json` — описание версии (создаётся при сборке).

Не входят: `data`, `exports`, документация, `tests`, `tools`, `cloud`, `.github`, `desktop.ini`, `.git`.

`manifest.json`:

```json
{
  "version": "2026.10.24.1",
  "commit": "da9314f…",
  "publishedAt": "2026-10-24T09:05:12Z",
  "notes": ["feat: program updates through the cloud", "…"],
  "files": [
    { "path": "get-comp-info.ps1", "sha256": "…", "size": 15873 }
  ]
}
```

`notes` — заголовки коммитов с предыдущего тега `v*` (для первой версии — последние 20 коммитов). Консоль и веб показывают их как «Что нового».

## Выпуск версии

Закоммитьте свои изменения и запустите `tools/release.BAT`. Скрипт:

1. Проверяет, что ветка `main`, нет незакоммиченных изменений, здесь есть все коммиты из GitHub и с прошлого тега есть что выпускать.
2. Прогоняет тесты из `tests` (`-SkipTests` — пропустить; в GitHub Actions они всё равно идут).
3. Поднимает версию (`tools/update-version.ps1`) и собирает архив, как это сделает GitHub Actions.
4. Показывает номер версии и список изменений и спрашивает подтверждение (`-Yes` — не спрашивать).
5. Коммитит `chore: version …`, ставит тег `vВЕРСИЯ` и отправляет `main` с тегом одним атомарным push.
6. Ждёт запуск в GitHub Actions и сообщает результат со ссылкой (`-NoWait` — не ждать).

Если что-то не прошло до push, версия в `console-ui.ps1` возвращается обратно и в GitHub ничего не уходит. Если не прошла сама публикация в Actions, номер уже занят тегом: исправьте ошибку и выпустите следующую версию.

Вручную то же самое: `tools/update-version.BAT`, коммит, `git tag vВЕРСИЯ`, `git push origin main --tags`.

GitHub Actions (`.github/workflows/release.yml`) по тегу `v*` на Windows-раннере:

1. Запускает все тесты из `tests` в Windows PowerShell 5.1.
2. Собирает архив `tools/build-release.ps1`. Если тег не совпадает с версией в `console-ui.ps1`, сборка останавливается.
3. Получает OIDC-токен GitHub с аудиторией `comp-info-release` и отправляет архив `tools/publish-release.ps1` в `POST /api/release`.

Облако принимает архив, только если токен подписан GitHub, выдан запуску репозитория `bobanko/get-comp-info` (`RELEASE_REPOSITORY` в `cloud/wrangler.jsonc`) по тегу, и тег совпадает с версией в архиве. Затем проверяет каждый файл по `manifest.json`, сохраняет версию и делает её текущей. Повторно опубликовать ту же версию нельзя. Если выпуск сломан, выпустите следующую версию или сделайте текущей предыдущую на странице «Версии программы».

Публиковать версии можно только так. Личные ключи консоли, в том числе ключи администраторов, публиковать не могут: потерянная флешка не позволит разослать всем свою «версию программы». Папка `tools` в архив версии не входит.

Собрать архив локально для проверки: `powershell -File tools\build-release.ps1` (результат в `dist\`, папка исключена из Git). Локальный сервер разработки (`npm run dev` в `cloud`) принимает публикацию без токена: `tools\publish-release.ps1 -Package dist\comp-info-<версия>.zip -ApiUrl http://localhost:8787/api/release`.

## Обновление в консоли

Пункт главного меню «Обновить программу» или `update-program.BAT`. Работает в той копии программы, из которой запущен, то есть на флешке или на компьютере.

1. **Ключ** берётся так же, как при синхронизации: из `cloud-key.txt` или вводом с предложением сохранить.
2. **Проверка версии.** `GET /program/latest` возвращает текущую версию в облаке. Скрипт сравнивает её с `$script:toolboxVersion`:
   - версии совпадают — «Установлена последняя версия», больше ничего не делается;
   - в облаке новее — показываются обе версии и «Что нового»;
   - в облаке старее (администратор откатил выпуск) — предлагается откат с явной пометкой.
3. **Подтверждение.** `Enter` устанавливает, `Esc` отменяет.
4. **Загрузка** в `.update\comp-info-<версия>.zip` внутри папки программы, без записи на системный диск. SHA-256 архива сверяется с облаком; при расхождении архив удаляется.
5. **Распаковка и проверка.** Каждый файл сверяется с `manifest.json` по размеру и SHA-256, допускаются только файлы программы в корне. Любое расхождение или лишний файл останавливает обновление, и программа остаётся нетронутой.
6. **Резервная копия** текущих файлов программы сохраняется в `.update\backup-<текущая версия>-<дата>\`.
7. **Замена.** Каждый файл записывается через временный файл с заменой (с повтором, если файл ненадолго занят антивирусом) и снова проверяется по SHA-256.
8. **Удаление устаревших файлов.** Файлы программы в корне (`*.ps1`, `*.BAT`, `*.cmd`), которых нет в новой версии, удаляются. Они остаются в резервной копии.
9. **Завершение.** Показывается «Программа обновлена до версии …», затем меню перезапускается уже с новой версией.

Если шаг 7 или 8 завершился ошибкой, файлы автоматически восстанавливаются из резервной копии, а добавленные удаляются. Если не удалось и это, на экране показывается путь к резервной копии для ручного восстановления. Код завершения при ошибке — 1.

Обновление **никогда не трогает**: `data`, `exports`, `cloud-key.txt`, `cloud-state.json`, `desktop.ini`, `.update` и любые подпапки. Собственные скрипты в корне папки программы держать нельзя: обновление удалит их как устаревшие (они останутся в резервной копии). `cloud-config.json` входит в версию и обновляется вместе с программой.

Хранятся только две последние резервные копии и архивы, более старые удаляются после успешного обновления.

### Ограничения

- Если в папке программы есть `.git`, это копия для разработки. Обновление отказывается работать и предлагает обновляться через Git.
- Перед обновлением закройте сборщик, просмотрщик и другие окна программы.
- Синхронизация с облаком тоже проверяет версию и в итоге показывает подсказку, если вышла новая.
- Первая версия с пунктом «Обновить программу» попадает на флешку вручную (скопировать файлы программы). Дальше флешка обновляется сама.

## Облако

Подробности в [CLOUD.md](CLOUD.md):

- архивы версий хранятся в D1, в таблице `program_releases`. Размер архива ограничен 1 МБ, сейчас он около 45 КБ;
- `GET /api/client/program/latest` и `GET /api/client/program/{version}/package` — для ролей `harvester`, `editor`, `admin`;
- `POST /api/release` — только с OIDC-токеном GitHub Actions этого репозитория, не с личными ключами;
- в веб-интерфейсе `admin` видит список версий и может сделать текущей любую из них (откат).
